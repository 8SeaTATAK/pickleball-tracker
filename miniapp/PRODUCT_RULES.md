### 3. 评分与级别规则 v1（替换现有评分算法）

规格见 [docs/rating-rules-v1.md](docs/rating-rules-v1.md)，文中算例已逐项验算，与公式一致。现有算法（`cloudfunctions/api/lib/rating.js`）是早期简化版，按以下阶段替换：

1. **评分引擎**：按赛制区分 s 和 L；表现差限制 ±0.25；K 由可靠度决定（0.60 → 0.25）；单局上限 0.08（定级期 0.15）；单日上限 ±0.30；可靠度按 180 天内有效局数计算（90 天内 1.0，90–180 天 0.5）；起始分（DUPR 起始可靠度 30%，自评 0%）；参数集中写成配置。
2. **录分流程**：活动或对局可选 5 种赛制；三局两胜逐局录入；限时局；比赛类型 M（联赛 1.2、活动场 1.0、自由录入 0.5）；24 小时确认与异议；同日同四人第 3 局起 M 打 5 折；队伍分差超过 1.5 时 M 打 5 折。
3. **级别与管理**：8 档称号和定级期显示「萌新·定级中（3/10）」；升降级缓冲（升 +0.050 连续 3 局，降 −0.100 连续 5 局，升级后 5 局保护期）；「待复核」；管理员调级（填原因，分数设为新档下限 + 0.100）；定级期和待复核不进排行榜；撤销某局后从该局起重算所有受影响球员；个人页显示到下一级的进度。
4. **问卷与校准**：自评问卷已由「水平自测」（10 个维度，见「已实现」第 11 条）取代；约 200 局后拟合各赛制的 s。

实现前需要和规则作者确认的问题（原文末尾的 4 项待确认之外）：
- **定级局数前后不一致**：可靠度 = 有效局数 × 10%，60% 只需 6 个满权重局，但文中又说「一般打满约 10 局」，显示也是「3/10」。是把 10% 改成 6%（10 局到 60%），还是显示改成「3/6」？
- **DUPR 起始可靠度 30% 怎么并入公式**：可靠度完全由 180 天内的局数算出，30% 是固定加成、会随时间衰减的虚拟 3 局，还是只在第一局前有效？
- **按局计分需要改录分界面**：现在一场对局只录一个比分，三局两胜要改成逐局录入。
- **撤销后重算**：现有做法只撤销该局自己的影响；规则要求从该局起按时间顺序重放所有后续比赛，数据量大时需要后台任务。
- **单日上限 ±0.30**：按自然日（悉尼时间）还是滚动 24 小时？
- **混双**：初期并入双打，需要在活动或对局上标记混双，方便以后拆分。

### 13. 活动类型：普通 Social / DUPR 计分场（2026-11-24 提出）

**发布活动时必须选择**：「普通 Social」还是「DUPR 计分场」。

- **普通 Social**：谁都能报名；比分照常算俱乐部评分；只有四个人都有 DUPR ID 的局才进入 DUPR 导出。
- **DUPR 计分场**：**没有 DUPR ID（接入 API 后为「没有关联 DUPR 账号」）就不能报名，硬性拦截**，弹窗说明原因并给「去填 DUPR ID / 注册教程」入口；全部局都进入 DUPR 导出；活动卡片和详情页显示「DUPR」标识。
  - 拦截在云函数里做（`signup` 返回错误代码，例如 `err_needDuprId`），前端只负责提示，不能只靠前端。
  - 所有进入名单的路径都要检查：本人报名、带人报名（被带的朋友也要有 DUPR ID，临时球员没有 ID 就不能被带进 DUPR 场）、管理员代加、候补转正。
  - 报名后才删掉 DUPR ID 的：保留报名，但管理员名单里标红提醒；导出时这些局照样列为缺 ID。
  - 活动已经有人报名后，不允许从「普通 Social」改成「DUPR 计分场」（或改之前提示管理员有几个人没有 DUPR ID）。
- **用户资料**：加 **DUPR ID** 字段（6 位字母数字，DUPR 个人资料页可查），和现有的 DUPR 分数（第 4 条）放在一起。
- **报名提醒**：普通 Social 报名时，没填 DUPR ID 的人看到一条轻提示，不拦截。
- **排对阵**：普通 Social 里尽量把有 DUPR ID 的四个人排在同一场，让能上传的局更多。
- **导出 DUPR 比分**（管理员，活动结束后）：按 DUPR 俱乐部后台的官方 CSV 模板生成，一局一行；列出因缺 DUPR ID 没能导出的局和缺 ID 的人；赛后补填了 ID 的可以重新导出。**官方模板等 DUPR Club 批下来后拿到再做。**
- 以后接入 DUPR API（第 12 条）时，「导出」换成「直接上传」，活动类型不变。

### 14. 比分确认：双方各一人确认（2026-11-24 确定）

适用于没有专职裁判的活动（例如 8 人转，所有人都上场）。和评分规则 v1「俱乐部活动场：双方各有一人确认比分，或管理员确认」一致。

- 一局打完，**任一方的一名球员**在小程序里录比分，状态为「待确认」。
- **对方的一名球员**点「确认」才生效；点「有异议」则转给管理员裁决（可改比分）。同一方的人不能替对方确认。
- **管理员**可以直接确认或修改任何一局。
- 录了比分但 **24 小时内**没人确认的，这一局不计分（规则 v1）；管理员仍可补确认。
- 只有**已确认**的局才计入俱乐部评分、积分榜，才能导出到 DUPR。
- 录分人或确认人改了比分，要重新确认；所有修改留记录（谁、什么时候、改前改后）。
- 有裁判的活动（裁判或管理员录入）不需要再确认。

### 15. 每周固定活动 + 周五 8 人转模板（2026-11-24 提出）

- **周期活动**：管理员设置一次（每周几、时间、场地、人数、费用、活动类型），系统每周自动发布下一场，报名每周独立。可以跳过某一周、修改单次。

### 1. 头像、昵称修改频率

- 距离上次修改**满 30 天**才能再改，昵称和头像分开计时。
- 注册后**第一次设置不计入**。
- **临时球员不受限制**（由管理员维护，没有自己的账号）。

### 11. 水平自测

- 入口：「我的」九宫格第二行第一个（原「等级标准」移到下方列表，自测结果页也有入口）。
- 10 个维度：正手、反手、发球、接发、Dink 小球、截击 / Block、第三拍 / 过渡、稳定性 / 非受迫失误、移动 / 双打站位、战术 / 决策。每个维度 5 档，记 1–5 分，一屏一题，有进度条、上一题 / 下一题，最后一题「保存并查看结果」。
- 换算：平均分 < 2 → 2.5，< 3 → 3.0，< 4 → 3.5，≥ 4 → 4.0。最高只给 4.0，更高要在比赛里打出来（规则 v1：自评只有这四档）。
- 结果页：建议起始水平 + 称号和等级描述、各项得分条、最弱两项的下一档目标（同分按题目顺序）、重新测试。
- 结果独立保存在 `users.selfTest = { answers, rating, avg, at }`，不改评分。
- 设为等级：小程序里还没打过比赛时可一键设为起始水平（`saveSelfTest` 的 `apply`）；网页预览里设为「匹克球等级（自评）」，受 30 天限制，已填 DUPR 的只显示结果。小程序做完匹克球等级（第 4 条）后改成和预览一致。
- 代码：计分 `cloudfunctions/api/lib/selfTest.js`（小程序 `utils/selfTest.js` 是同一份，测试会检查）；文案 `i18n.js` 的 `st_*`；页面 `pages/selftest/selftest`；预览 `viewSelfTest` / `viewSelfResult`。
