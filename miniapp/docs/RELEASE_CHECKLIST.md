## 二、需要你在后台操作（代码改不了）

1. **主体和备案**：2023 年 9 月起，新小程序上架前必须完成小程序备案。个人主体不能做含用户发布内容（UGC）和社交类的小程序，俱乐部、活动、昵称都算 UGC，建议用企业主体注册。在澳洲的话，需要确认是用国内公司主体，还是海外主体注册（海外主体的类目和备案要求不同，以后台提示为准）。
2. **AppID 和云环境**：`project.config.json` 里 `touristappid` 换成真实 AppID；`miniprogram/app.js` 的 `ENV_ID` 换成云开发环境 ID。
3. **服务类目**：在「体育」大类下选与「赛事 / 活动组织、计分」最接近的类目，按后台要求上传资质。审核会对照类目检查功能，不要选「工具」再放社交功能。
4. **用户隐私保护指引**（后台 → 设置 → 服务内容声明）：至少声明以下收集项及用途：
   - 微信昵称、头像：显示在个人资料、名单和积分榜
   - 剪贴板：复制俱乐部邀请码
   - 用户发布的内容（俱乐部、活动信息）：俱乐部运营
   - 以后加选场馆位置（`wx.chooseLocation`）、相册上传时，要回来补充
5. **云函数部署**：右键 `cloudfunctions/api` →「上传并部署：云端安装依赖」，确保 `config.json` 一起上传（内容安全接口的权限在里面）。
6. **数据库**：按 README 建 7 个集合，权限都设为「仅管理端可读写」。
7. **审核说明和测试账号**：审核员没有俱乐部，看不到主要功能。提交时在「审核说明」写清楚：首页 → 创建俱乐部 → 发布活动 → 报名 → 生成对阵 → 录分；或者提前建一个演示俱乐部，把邀请码写进审核说明。
8. **真机检查**：开发者工具「真机调试」走一遍主流程，特别是选头像、填昵称时是否弹出隐私授权。

## 三、对照同类产品，建议上线后再做

参考了 Pickleheads（活动报名、候补、轮转对阵）、CourtReserve（俱乐部和场地管理）、DUPR（评分）的公开功能介绍。和它们相比，我们的核心流程（报名 → 候补递补 → 自动对阵 → 录分 → 评分 → 积分榜）已经齐全，下面几项是它们普遍有、我们还没有的，按价值排序：

1. **活动提醒**（订阅消息）：开赛前提醒、候补转正通知。同类产品最常用的功能，需要先在后台申请订阅消息模板。
2. **签到**：组织者现场勾选到场的人，未到场的不进对阵。
3. **活动分享海报**：生成带小程序码的图片发到微信群，比分享卡片更容易被看到。
4. **匹克球等级（DUPR / 自评）和胜率、裁判记录页**：网页预览已经做好，小程序还没做（见 `PRODUCT_RULES.md` 第 2、4 条）。

## 四、提交前避免的写法

- 对外文案（小程序简介、分享标题）不要写「模拟 DUPR」「DUPR 官方」这类说法，写「俱乐部评分」。DUPR 是别家的商标；界面里让用户填自己的 DUPR 分数、说明「参考 DUPR 原则」没问题。本轮已把界面里的「模拟 DUPR」改成「俱乐部评分」。
- 不要出现点了没反应、「即将推出」「敬请期待」的按钮，审核会按「功能不完整」驳回。目前小程序里没有这类按钮。
- 不要出现付费入口（VIP、充值），在接入微信支付之前小程序里都不显示。目前小程序里没有。
